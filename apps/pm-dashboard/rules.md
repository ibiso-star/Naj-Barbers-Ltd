### 8.3 Code quality & cleanup
Define these conventions during the single intake, before splitting; they
move into `rules.md` with this section:

- **Naming conventions:** PascalCase React components and files for components; camelCase functions and variables; kebab-case route folders; snake_case database columns, mapped to camelCase domain types in the repository layer only
- **Comment policy:** comment why, not what; every non-obvious constant, RLS policy and trigger gets a one-line reason; no commented-out code
- **Linter/formatter:** ESLint 9 flat config with eslint-config-next (core-web-vitals + typescript); `tsc --noEmit` strict mode; both run in CI
- **Error surfacing:** repository methods throw typed errors; the store catches them, rolls back optimistic state and shows a toast with the message; nothing is silently swallowed; every route has error and not-found boundaries
- **Retry/timeout conventions:** no automatic retries on writes (avoids duplicate inserts); users retry from the toast. Realtime reconnects are handled by supabase-js; on reconnect the store refetches the workspace snapshot
- **Commit message format:** imperative, sentence-case subject under 72 characters, body explaining why
- **Branch naming:** `<author>/<short-description>` or the assigned `claude/<slug>` branch for agent sessions
- **PR size/scope convention:** one feature or fix per PR; standards documents updated in the same PR as the code that changes them
