# Code and security review — 2026-09-30

**Reviewer:** Claude Code (AI agent). The release owner still has to confirm

**Scope:** everything under `apps/pm-dashboard/` at the commit that adds this file.

## SEC-014 — SQL injection, XSS, CSRF (checked, not assumed)

- **SQL injection:** the browser never builds SQL. Every query goes through supabase-js/PostgREST, which sends filter values as parameters. The only server-side SQL is in `supabase/migrations/0001_init.sql`, where functions use typed arguments and no dynamic `EXECUTE`. `grep -rn "execute\|\.sql" src` finds no raw SQL.
- **XSS:** React escapes everything it renders. `grep -rnE "dangerouslySetInnerHTML|innerHTML|eval\(|new Function" src` returns nothing. User text (titles, descriptions, subtasks) only ever appears as text nodes, and activity messages are built from strings, not HTML.
- **CSRF:** database writes go from the browser straight to PostgREST with the JWT in the `Authorization` header, so a cross-site form can't forge them. The only route that relies on a cookie is `GET /auth/callback`. It exchanges a single-use PKCE code, and a CSRF attacker can't obtain the verifier. `next` is restricted to same-origin paths (`safeNextPath`, which blocks open redirects). There are no cookie-authenticated POST route handlers or server actions.
- **Headers:** `X-Frame-Options: DENY`, `nosniff`, a strict referrer policy and a restrictive permissions policy are set in `next.config.ts`. A CSP is not set yet and is noted as a follow-up.

## SEC-019 — secrets kept out of logs

The app has no server-side logging, and ESLint's `no-console` rule (only
`warn`/`error` allowed) runs in CI. `grep -rn "console\." src` returns
nothing, so no tokens or credentials are ever logged. Supabase's own logs are
outside this codebase.

## SEC-002 — session storage (NOT checked: partially met)

`@supabase/ssr`'s `createBrowserClient` keeps the session in **cookies**, not
`localStorage`. See `node_modules/@supabase/ssr/dist/main/createBrowserClient.js`,
where `storage` is its cookie adapter. Those cookies have to be readable by
JavaScript so the browser client can attach the access token, so they are
**not httpOnly**. That falls short of the control's wording. Closing the gap
means routing data access through server-side handlers, which is a design
change (see `decisions.md` D-002). The control stays open.

## PROD-021 / PROD-022 — fabricated content

- Demo mode shows fictional sample data, marked "Demo data" in the sidebar and in `src/lib/data/seed.ts`. It must never reach production. PROD-022 stays **open** until the release build is confirmed to run in Supabase mode with no seed applied.
